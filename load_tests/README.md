# Isolated event load test

Run this against the separate load stack only. Its PostgreSQL and Redis volumes, upload directory, and web port are distinct from the real event. The Locust script rejects all other ports unless edited.

```powershell
docker compose -f load_tests/docker-compose.yml up -d --build
.\load_tests\start-worker.ps1 -Workers 2
$env:LOAD_TEST_ISOLATED='1'
$env:LOAD_PROFILE='contestants'
locust -f load_tests/locustfile.py --headless -u 100 -r 10 -t 5m --host http://127.0.0.1:18000 --csv load_tests/data/contestants
.\load_tests\stop-worker.ps1
docker compose -f load_tests/docker-compose.yml down
```

The load worker uses fake results, so queue and API measurements do not establish real FarmCraft evaluator throughput. For a real engine benchmark use `python load_tests/benchmark_simulations.py --levels 1,2,4 --games 8` after building the evaluator image. Record machine CPU, RAM, disk, queue wait, p50/p95/p99 response latency, failed requests, and completion rate from the Locust CSV and Control Room. Do not use `down -v` unless you intentionally want to discard the isolated test volume.

The `contestants` profile signs 100 unique test teams in, uploads the fixture, submits sandbox jobs, polls status, and sends participant heartbeats. Official Round 1 and Round 2 jobs require a real evaluator worker; fake simulation is rejected for competition jobs. The `mixed` profile adds public spectators and therefore creates fewer than 100 authenticated teams at 100 total users. Neither profile writes the production leaderboard.

The isolated dashboard test credential is `load-test-organizer` at `http://127.0.0.1:18000/admin`. It is intentionally limited to this loopback-only rehearsal stack; the real event uses the private password generated by `start-server.ps1`.

For a full functional run, build the evaluator image, start the isolated stack, start a **real** worker with `./load_tests/start-worker.ps1 -Workers 1 -RealEvaluation`, and run `python load_tests/bootstrap_round1.py` on a fresh stack. This uploads and tests five reference bots, selects them, and opens Round 1. Then run `python load_tests/identity_smoke.py` to verify shared identity, upload, a real 20-game official result, leaderboard, organizer recovery, and cross-team access. Run these only against port `18000`.

For Control Center actions with the isolated fake worker, run `python load_tests/control_center_smoke.py`. It exercises team sessions, suspension and blocking, persistent event settings, worker pause/resume, queued and running cancellation, pipeline state, and audit history.

For the actual Docker evaluator path, `python load_tests/remote_real_smoke.py` validates sandbox and official matches, leaderboard update, cancellation, and Docker container cleanup. `python load_tests/two_round_http_smoke.py` closes qualification, finalizes the configured top qualifiers, starts a real Round 2 bracket, and checks champion persistence. These scripts change the isolated event state; run them in that order after the identity and Control Center smoke checks. Never set `LOAD_TEST_FAKE_SIMULATION=1` on the production worker.

For browser coverage, install optional Playwright Python support (`python -m pip install playwright`) and run `python load_tests/ui_smoke.py` with Chrome installed. It visits all eight contestant and thirteen admin sections, checks JavaScript and server errors, broken images, mobile entry layout, and the champion banner when a tournament is complete. Screenshots are written to `load_tests/data/`.
