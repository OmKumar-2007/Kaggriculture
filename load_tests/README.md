# Isolated event load test

Run this against the separate load stack only. Its PostgreSQL and Redis volumes, upload directory, and web port are distinct from the real event. The Locust script rejects all other ports unless edited.

```powershell
docker compose -f load_tests/docker-compose.yml up -d --build
.\load_tests\start-worker.ps1 -Workers 2
$env:LOAD_TEST_ISOLATED='1'
$env:LOAD_PROFILE='contestants'
locust -f load_tests/locustfile.py --headless -u 100 -r 10 -t 5m --host http://127.0.0.1:18000 --csv load_tests/data/contestants
.\load_tests\stop-worker.ps1
docker compose -f load_tests/docker-compose.yml down
```

The load worker uses fake results, so queue and API measurements do not establish real FarmCraft evaluator throughput. For a real engine benchmark use `python load_tests/benchmark_simulations.py --levels 1,2,4 --games 8` after building the evaluator image. Record machine CPU, RAM, disk, queue wait, p50/p95/p99 response latency, failed requests, and completion rate from the Locust CSV and Control Room. Do not use `down -v` unless you intentionally want to discard the isolated test volume.

The `contestants` profile signs 100 unique test teams in, uploads the fixture, submits sandbox and official jobs, polls status, and sends participant heartbeats. The `mixed` profile adds public spectators and therefore creates fewer than 100 authenticated teams at 100 total users. Neither profile writes the production leaderboard.

The isolated dashboard test credential is `load-test-organizer` at `http://127.0.0.1:18000/admin`. It is intentionally limited to this loopback-only rehearsal stack; the real event uses the private password generated by `start-server.ps1`.

For a shorter identity and permissions check, run `python load_tests/identity_smoke.py` while the isolated stack and its worker are running. It registers disposable teams, verifies the shared Bot Lab and Tournament identity, uploads a bot, checks an official result and leaderboard, exercises organizer recovery, and checks cross-team access. Run it only against the isolated port `18000`.

For Control Center actions with the isolated fake worker, run `python load_tests/control_center_smoke.py`. It exercises team sessions, suspension and blocking, persistent event settings, worker pause/resume, queued and running cancellation, pipeline state, and audit history.

For the actual Docker evaluator path, stop the fake worker, start `./load_tests/start-worker.ps1 -Workers 1 -RealEvaluation`, and run `python load_tests/real_pipeline_smoke.py`. This validates a real sandbox match, eight-game official scoring and leaderboard update, contestant runtime failure without a new score, running Docker cancellation, and container cleanup. It can take several minutes. Never set `LOAD_TEST_FAKE_SIMULATION=1` on the production worker.
